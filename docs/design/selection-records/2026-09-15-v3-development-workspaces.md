# 三代开发工作区与版本治理选择记录

- 日期：2026-09-15
- 状态：已确认
- 决策人：项目负责人
- 适用范围：三代前后端开发、联调、测试与版本备份

## 已比较方案

1. **两个 Git Worktree（采用）**：保留现有 Monorepo，通过独立目录和分支隔离前后端修改，共享契约仍可由 Git 同步。
2. 直接把源码移动到顶层 `frontend/`、`backend/`：目录直观，但会同时破坏 npm workspace、Electron 打包路径和既有脚本，迁移风险高。
3. 拆成两个独立仓库：隔离最彻底，但当前单机产品规模不足以抵消契约同步、版本协调和构建编排成本。

## 最终选择

- 前端工作区：`三代开发/frontend`，分支 `codex/v3-frontend`。
- 后端工作区：`三代开发/backend`，分支 `codex/v3-backend`。
- 前端负责 `apps/web`、生成式 API 客户端及浏览器 E2E。
- 后端负责 `apps/api`、`apps/qq-bot`、数据库迁移、任务进程、接口与负载测试。
- `packages/contracts` 为共享边界，由后端先冻结契约，前端同步后消费。
- 已确认的 Electron、React、Fastify、SQLite 和 TypeScript 技术栈保持不变；不采用 PySide6。

## 版本和备份规则

- 后端开发标签：`be-v3.0.0-dev.N`。
- 前端开发标签：`fe-v3.0.0-dev.N`。
- 集成候选标签：`v3.0.0-alpha.N`。
- 只有通过对应测试、类型检查和构建门禁的批次才能打标签并推送到 `origin`。
- 正式安装包和便携包必须在源码验证完成并取得“确认打包”后生成。

## 影响与回退

Worktree 只隔离检出目录，不复制 Git 历史。删除某个 Worktree 不会删除已推送分支；如需回退，重新从远端分支创建工作区即可。主目录中的用户文件、运行数据和未跟踪资料不进入开发分支。

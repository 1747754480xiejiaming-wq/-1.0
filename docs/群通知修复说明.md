# 群通知修复说明

2026-09-04。

## 查明的原因

旧版把 QQ SDK 抛出的所有错误统一显示为「发送结果未确认，请核对群聊后再发送」，因此老师无法判断是权限、认证、限流还是网络问题。

本轮向老师选定的「学生工作群 · 1班」实际测试发送：

> 选课截至时间为9月9号，还没选课的同学尽快了

QQ 返回 **HTTP 400，业务码 40034105，主动消息失败，无权限**。本次通知未送达；失败记录已保存。没有伪造消息 ID，没有复用历史消息来绕过主动消息权限，也没有重放此前失败的通知。

## 程序修复

- 单独识别 40034105，明确提示群主检查该群机器人的主动发言授权。
- 区分认证错误、403 权限问题、429 频率/额度限制、其他明确拒绝及结果不明。
- 不保存 SDK 原始错误正文，避免记录 URL、群标识、凭证或消息正文。
- 发送成功需要收到有效的 QQ 消息 ID；回执写入数据库，可供后续核验。
- 队列回写失败只重试本地结果，不重新调用 QQ 发送。结果不明仍提示先核对群聊。
- 增加「复制通知」，支持在 QQ 手动粘贴；「重新编辑」回填正文和失败群，老师再次点击发送才会新建请求。

## 当前需要处理的外部条件

机器人已经能够连接 QQ，并不表示获得了主动群消息权限。请群主在手机 QQ 的群资料 → 群机器人 → 对应机器人设置中检查「机器人主动在群聊内发言」开关并开启。若没有该开关或仍被拒绝，再在 [QQ 开放平台](https://q.qq.com/) 核实应用能力或联系平台支持。授权按实际群与机器人生效，更换机器人需要重新核对。

依据 [腾讯 SDK 使用指南](https://github.com/tencent-connect/qqbot-nodejs/blob/main/USAGE.md)，没有入站消息 ID 的群消息走主动推送路径，受平台主动消息限制；即时回复学生新消息属于另一种消息流程。本次按老师要求执行主动通知，没有改成伪装的被动回复。

群主授权并确认应用能力后，在「一键通知」找到本次失败记录，点击「重新编辑」，核对群聊和内容，再点击发送。平台成功回执只表示 QQ 接受，不表示学生已读。
